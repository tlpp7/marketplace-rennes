## Périmètre et décision
V0.2 = quatre profils fictifs, annuaire, filtres et fiches, avec l'API des profils approuvés issue de PostgreSQL.
La recette locale ne vaut pas homologation de la mise en production. L'environnement public doit disposer d'une URL HTTPS contrôlée et d'un opérateur responsable de son hébergement.

Statuts autorisés : **PASS** (preuve archivée), **FAIL** (écart), **N/A** (hors périmètre justifié), **À FAIRE**.

## Commandes de recette

### Locale avec PostgreSQL (pas un déploiement public)
```bash
cd /workspaces/marketplace-rennes
bash scripts/setup-local.sh
set -a; source .env.local; set +a
npm run db:check
node --test scripts/check-profiles-v02.mjs
node --test scripts/check-directory-v02.mjs
npx playwright test tests/e2e/profiles-v02.spec.mjs --workers=1 --reporter=list
```

### Staging / production : lecture seule
```bash
node scripts/validate-v02-production.mjs --url https://VOTRE-DOMAINE-VALIDÉ --json rapport-v02.json
```
Fournir uniquement une URL dont vous êtes administrateur. Ce script est non destructif. Ne pas utiliser d'adresse privée d'un tiers.

## Conditions de validation opérationnelle

**GO V0.2** : tous les tests automatiques obligatoires PASS, preuves archivées, contrôle des accès 017–019 PASS en préproduction, accès HTTPS, supervision, sauvegarde/restauration et revue humaine 014, 022, 023, 026 approuvés, aucune vulnérabilité critique/élevée non acceptée formellement.

**NO GO** : une fuite de données, des profils non approuvés visibles, HTTP sur une destination publique, des 5xx répétés, des sauvegardes non restaurables, ou une vulnérabilité majeure sans traitement ou décision de risque documentée.

La version ne doit pas être annoncée « validée pour production » à partir des seuls tests sur Codespaces.
